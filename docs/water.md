# Воксельная вода

Запуск независимого от рендера примера:

```sh
cargo run -p physics_voxel --example water
```

В закрытом бассейне падают 64 полные ячейки (512 единиц воды), затем вода
растекается по дну. Пример проверяет общий объём после каждого шага.

`physics_voxel::step_water` принимает снимок мира, реестр восьми уровней воды,
активные координаты и лимиты работы. Сначала вода заполняет ячейку снизу,
затем переносит по единице к более низким горизонтальным соседям.
Каждая ячейка содержит от 0 до 8 единиц; нулевой уровень соответствует воздуху.
Порядок обработки детерминирован, повторные активные координаты исключаются.
Перенос внутри шага использует уже обновлённые количества соседей.

Результат — `WaterPlan::Transaction { edit, next_active }` либо `Settled`.
Применяйте `edit` через `World::commit`; только после успешного commit заменяйте
активный список на `next_active`. При конфликте ревизий перепланируйте шаг.
Транзакция проверяет ревизии всех прочитанных чанков, включая препятствия.
После внешнего изменения мира активируйте изменённую ячейку и шесть соседей,
чтобы вода снова начала двигаться. Частоту шагов задаёт вызывающий код.

Незагруженные чанки и превышение лимитов возвращают ошибку до изменения мира.
Модель сохраняет объём, но допускает остаточные различия соседних уровней
в одну единицу. Это клеточное растекание: здесь нет скорости жидкости,
волн, вязкости, плавучести тел или напора в сообщающихся сосудах.
Восемь состояний задают объём для физики; высота поверхности требует
отдельной поддержки в мешере.

## Разные жидкости

`step_liquid` использует тот же решатель с `LiquidStates` (восемь уровней
одной жидкости) и `LiquidFlow`. Регистрируйте отдельные, непересекающиеся
наборы состояний для воды, масла и лавы.

| Профиль | Максимум вниз за шаг | Максимум в стороны за шаг |
| --- | --- | --- |
| `LiquidFlow::WATER` | 8 | 4 |
| `LiquidFlow::OIL` | 2 | 2 |
| `LiquidFlow::LAVA` | 1 | 1 |

Это условные игровые скорости, а не измеренные вязкости. Можно задать свои
лимиты от 1 до 8. Горизонтальный перенос ограничен также одной единицей на
соседа за шаг. `step_water` сохраняет прежнее поведение и вызывает профиль воды.

Для каждой жидкости храните свой активный список. Планируйте и применяйте
их шаги последовательно к актуальному миру, чтобы конфликтующие записи
не затёрли друг друга. Чужая жидкость блокирует обычный поток. Для расслоения используйте отдельную
фазу ниже. Смешивание, химические реакции и теплообмен пока не реализованы.

## Расслоение по плотности

`LiquidMaterial { states, density }` задаёт положительную относительную
плотность; важен порядок значений. Например, вода — 1000, масло — 800.
`step_liquid_layers(view, registry, materials, active, source, budget)`
планирует обмен соседних вертикальных ячеек, если верхняя жидкость тяжелее.
Уровень наполнения перемещается вместе с материалом, поэтому объём каждого
вида сохраняется. При равной плотности обмена нет.

Одна ячейка участвует максимум в одном обмене за шаг. Наборы состояний
материалов должны быть непересекающимися. Результат применяйте через
`World::commit`, затем выполняйте обычное растекание на обновлённом мире.
Изменённые ячейки и соседей из `next_active` передавайте в следующие фазы
для всех затронутых жидкостей. Конфликт ревизий требует перепланирования.

Это дискретная сортировка целых ячеек, включая частично заполненные.
Она не моделирует непрерывную границу двух жидкостей внутри одного вокселя,
силу Архимеда для тел или скорость всплытия. В графическую сцену эта фаза
автоматически не подключена: вызывающий код задаёт материалы и цикл фаз.
