# Shared managed compute, geometry and colour resource budget

ComputeMemoryBudget provides one admission ledger per wgpu device for ComputeProgram job storage and GravityProgram resident/scratch storage. Terrain, water and voxel compute paths using ComputeProgram share that ledger. SceneRenderer mesh uploads, reserved geometry, eager LOD bundles, streamed LOD indices, skeletal source attributes, per-instance palettes/parameters and skeletal LOD indices now share this ledger. Uploaded scene colour mip chains, sampled colour attachments and HDR mip pyramids and per-draw MVP/material/view uniforms share it as well. Renderer retains the same accounting owner. Separate devices remain independent.

Configure with ComputeMemoryBudget::configure(device, max_bytes) before the first managed storage allocation; an existing unused Renderer/program owner receives the same configured limit. Admission rejects exhausted capacity with ComputeError::MemoryBudget before allocating a GPU buffer. Empty, unaligned and per-device oversized buffers retain their existing validation errors. A configured device budget cannot be silently changed by another program. Once unbounded allocations have been used, enabling a finite limit is rejected because old external/GPU references cannot be accounted retroactively.

There is no finite default storage limit yet. Unconfigured accounting measures live managed owners and preserves ordinary wgpu resource lifetime handling; it does not retain dropped jobs or measure driver-retained submissions/external clones. This preserves existing repeated generation and browser behavior until a complete retirement coordinator is connected.

An explicitly configured budget conservatively includes retired buffers: dropping a job alone does not prove GPU completion. The registry retains their storage and charges even when the last program/renderer is dropped. Native discard_retired destroys retired buffers and waits for completion before releasing charges. Discard any unsubmitted encoder, external buffer clone or binding that still uses retired storage before cleanup. Poll errors retain charges for retry. Cleanup never runs implicitly and blocks. Configure a finite limit only together with an explicit cleanup cadence.

Nonblocking retirement is available through begin_retirement(queue) and PendingComputeRetirement::try_finish on native and browser builds. Initiate it only after all uses of the retired buffers have been submitted to the budget device's own queue and future/unsubmitted uses discarded. The ticket retains buffers and charges until the queue callback is observed. Cancellation restores buffers to the charged retirement list; disconnected notifications return an error without releasing charges. A completed ticket is idempotent. Queue retirement is a terminal resource-lifetime signal, not evidence that a shader produced a valid result; device loss and compute-result validation remain separate concerns.

Automatic coordination across independent producers between frames, depth/MSAA/3D/compressed/environment texture paths, acceleration structures, readback staging and CUDA allocations are not included. Readback has its own bounded pool. These byte counts are managed buffer payload sizes, not measured physical VRAM or process RSS. GPU submissions and external resource ownership require further integration before this can be presented as an engine-wide GPU memory cap.

The compute_smoke fixture configures eight bytes across two programs on a physical device: two four-byte jobs fit, a third is rejected; submitted compute must still produce exactly 9; retirement stays charged until explicit cleanup, then replacement storage fits. Focused tests cover shared admission, retained retirement, device isolation and unchanged unconfigured lifetime behavior. The physical Apple M4 Max Metal fixture passed the eight-byte admission/retirement proof and all existing 1042 exact-result, resident snapshot, reload, dispatch validation and readback-pool checks. Native voxy_render/voxy_gpu examples compile. Six focused memory tests passed, including cancellation, disconnected notifications, configuring unused existing owners and unconfigured lifetime compatibility. The Metal fixture also passed nonblocking ticket retirement and idempotent completion. The wasm32 voxy_web library compilation passed. Strict Clippy remains blocked by twelve diagnostics in fluid_screen.rs; the new compute_memory module has no diagnostics in that run.

Mesh admission validates and charges an entire batch before creating its buffers. Eager LOD uploads admit four shared vertex/normal/material streams plus every index variant together. Shared streams retain one accounting owner across levels, including skeletal LOD levels; dropping one geometry does not retire buffers still owned by another. Reserved geometry uses the same five-buffer batch admission. A budget rejection returns SceneError::MemoryBudget and leaves the previously published geometry and accounting unchanged. Replacement requires enough headroom for old and new allocations to coexist; dropping old geometry after successful replacement retains its charge until explicit retirement.

The budget remains opt-in. Existing unconfigured scene/editor paths retain ordinary wgpu lifetime behavior, and this integration alone does not enable a default engine cap or automatic frame retirement. These preallocation checks prove configured payload admission, not recovery from driver allocation failure/device loss. Editor UI acceptance and other GPU backends require separate checks.

Physical Metal acceptance for the mesh extension passes shared compute/geometry exhaustion, preserved GPU vertex bytes on rejected replacement, no partial eager LOD/reservation charge, unique LOD stream ownership, explicit retirement and reuse. The existing real-GPU renderer suites additionally pass 17 tests including skeletal position/normal CPU comparisons and LOD draws. Seven focused budget/retirement tests pass; streamed LOD tests cover competing compute and charged retirement before recovery. Native editor compilation and wasm32 browser compilation pass. Current native window acceptance reports zero presented frames and SkippedOccluded, so it remains unverified. Evidence: artifacts/shared-mesh-memory-budget-2026-10-07.

Skeletal instance admission includes five geometry buffers, the joint palette and the compute parameter buffer in one batch. Immutable SceneSkinSource attributes share the same device ledger and remain charged while any instance retains the source. SceneSkinInstance retains its parameter owner alongside the binding, and its logical allocation_bytes derives from the actual geometry/palette/parameter buffer sizes rather than a second cached byte total. Caller residency limits remain independent per-model admission policies; they cannot bypass the device ledger.

Physical Apple M4 Max/Metal qualification for skeletal admission passes a 256-byte shared source and two 440-byte instances. A competing 36-byte compute owner leaves enough room for geometry plus palette but not the last 32-byte parameter buffer: the entire candidate is rejected with unchanged accounting and no partial retirement. After explicit compute retirement, the second instance fits. Further source/LOD admission rejects at the device cap; the first instance still produces GPU vertex positions matching CPU baking after rejection. Dropping one instance retains the shared source; a retained LOD keeps only its four shared streams and index buffer after the last instance retires. Explicit final retirement releases all charges to zero. Current suites pass 148 default renderer tests and 19 explicitly enabled physical GPU tests; browser compilation passes. Evidence: artifacts/shared-skeletal-memory-budget-2026-10-07. Full calibrated tissue motion, automatic/default retirement, remaining allocation classes, CUDA and other backends remain separate requirements.

Colour resource admission uses one mixed retirement queue, not a separate texture ledger. Managed 2D single-sample RGBA8/BGRA8 (linear/sRGB) and RGBA16Float payloads include every mip level and array layer with checked size/dimension limits. Scene material and planar capture bindings retain the same Arc texture owner; views do not count the image twice. The existing allocated_buffers/retired_buffers counts retain their buffer meaning; allocated_textures/retired_textures distinguish images, and allocated_bytes covers both classes. As before, these are payload bytes, not physical tiled/aligned VRAM. External raw texture clones/views/bindings and unsubmitted encoders must be discarded before explicit retirement. Unconfigured owner drops retain ordinary wgpu behavior; automatic/default engine retirement is still absent.

Ten focused tests include texture payload/invalid validation, shared ownership, mixed buffer/texture cancellation and disconnected fence notifications. Physical Metal qualification fills capacity with mesh, compute, 44 bytes of authored colour mips and a 56-byte NPOT HDR pyramid. New image/colour/HDR allocations reject before GPU creation; independent GPU textureLoad/readback verifies all original mip colours after rejection. Views do not add charge, mixed queue retirement retains charges until observed completion, then replacement fits. The 151 default renderer tests and 20 explicitly enabled GPU tests pass; wasm browser compilation passes. Numeric HDR mip, authored material mip and planar reflection fixtures pass separately (556 HDR half-float channel references, minification gray reference and planar HDR/PBR/Fresnel/roughness/frustum references). Evidence: artifacts/shared-colour-texture-budget-2026-10-07. This closes these managed colour paths, not every texture/allocation path or general driver OOM recovery.

SceneTransform retains its existing 256-byte uniform ABI through the same managed buffer owner. Valid matrix/view/material updates remain in-place and add no charge. Creating another transform on an exhausted configured device returns SceneError::MemoryBudget before allocating or changing existing uniforms. Dropped transform uniforms stay charged until explicit retirement; all external bindings/unsubmitted encoders must be discarded before cleanup. Physical Metal qualification fills the shared cap with mesh, image, compute and two independent transforms; a separate GPU compute program reads both uniform bindings after failed admission and verifies all 128 float values, including MVP/view/PBR updates without overwriting the second object. Evidence: artifacts/shared-transform-memory-budget-2026-10-07. This closes per-draw uniform admission, not automatic retirement or every renderer allocation.

SceneRenderer and SceneSkinner now retain the existing shared accounting owner even with zero resident/retired resources. An external budget handle can be dropped after cleanup without silently losing the configured limit while either scene producer remains alive. A formerly unbounded producer retains its allocation history, preventing retroactive finite configuration after its last resource drops. There is no new registry or per-producer ledger. If every program/renderer/resource/budget owner is destroyed, preserving configuration for the remaining raw device lifetime is still a separate lifecycle requirement. Two new no-op-device ownership regressions, all 154 default renderer tests, all 22 physical GPU tests and the browser build pass. Evidence: artifacts/scene-memory-owner-persistence-2026-10-07.
