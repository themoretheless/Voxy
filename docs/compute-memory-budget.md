# Shared managed compute-storage budget

ComputeMemoryBudget provides one admission ledger per wgpu device for ComputeProgram job storage and GravityProgram resident/scratch storage. Terrain, water and voxel compute paths using ComputeProgram share that ledger. Renderer retains the same accounting owner. Separate devices remain independent.

Configure with ComputeMemoryBudget::configure(device, max_bytes) before the first managed storage allocation; an existing unused Renderer/program owner receives the same configured limit. Admission rejects exhausted capacity with ComputeError::MemoryBudget before allocating a GPU buffer. Empty, unaligned and per-device oversized buffers retain their existing validation errors. A configured device budget cannot be silently changed by another program. Once unbounded allocations have been used, enabling a finite limit is rejected because old external/GPU references cannot be accounted retroactively.

There is no finite default storage limit yet. Unconfigured accounting measures live managed owners and preserves ordinary wgpu resource lifetime handling; it does not retain dropped jobs or measure driver-retained submissions/external clones. This preserves existing repeated generation and browser behavior until a complete retirement coordinator is connected.

An explicitly configured budget conservatively includes retired buffers: dropping a job alone does not prove GPU completion. The registry retains their storage and charges even when the last program/renderer is dropped. Native discard_retired destroys retired buffers and waits for completion before releasing charges. Discard any unsubmitted encoder, external buffer clone or binding that still uses retired storage before cleanup. Poll errors retain charges for retry. Cleanup never runs implicitly and blocks. Configure a finite limit only together with an explicit cleanup cadence.

Nonblocking retirement is available through begin_retirement(queue) and PendingComputeRetirement::try_finish on native and browser builds. Initiate it only after all uses of the retired buffers have been submitted to the budget device's own queue and future/unsubmitted uses discarded. The ticket retains buffers and charges until the queue callback is observed. Cancellation restores buffers to the charged retirement list; disconnected notifications return an error without releasing charges. A completed ticket is idempotent. Queue retirement is a terminal resource-lifetime signal, not evidence that a shader produced a valid result; device loss and compute-result validation remain separate concerns.

Automatic coordination across independent producers between frames, textures, meshes, acceleration structures, readback staging and CUDA allocations are not included. Readback has its own bounded pool. These byte counts are managed buffer payload sizes, not measured physical VRAM or process RSS. GPU submissions and external resource ownership require further integration before this can be presented as an engine-wide GPU memory cap.

The compute_smoke fixture configures eight bytes across two programs on a physical device: two four-byte jobs fit, a third is rejected; submitted compute must still produce exactly 9; retirement stays charged until explicit cleanup, then replacement storage fits. Focused tests cover shared admission, retained retirement, device isolation and unchanged unconfigured lifetime behavior. The physical Apple M4 Max Metal fixture passed the eight-byte admission/retirement proof and all existing 1042 exact-result, resident snapshot, reload, dispatch validation and readback-pool checks. Native voxy_render/voxy_gpu examples compile. Six focused memory tests passed, including cancellation, disconnected notifications, configuring unused existing owners and unconfigured lifetime compatibility. The Metal fixture also passed nonblocking ticket retirement and idempotent completion. The wasm32 voxy_web library compilation passed. Strict Clippy remains blocked by twelve diagnostics in fluid_screen.rs; the new compute_memory module has no diagnostics in that run.
