# GPU liquid density qualification — 2026-10-13

The renderer now exposes `LiquidDensityCompute`, which records density dispatches and snapshots in the caller-owned command encoder. Submission and device polling remain application-owned. `PendingLiquidDensity::try_candidate` never blocks; it yields a complete ABI-audited candidate or a compute/decoding error. A candidate is consumed once and still needs current-input physical admission.

The native liquid step accepts a density backend, audits its whole result against the original f64 formula, and falls back on rejection. Successful state publication is transactional. Boundary/image contributions, force evaluation, rheology, transport and adaptive stepping remain native. This audit still computes the CPU reference; no acceleration or FPS claim follows from correctness qualification.

Actual GPU evidence: six density fixtures (70 particles, 2415 pairs, three formulas, two smoothing radii), maximum relative error 2.193235462329663e-14; nine timesteps using the public dispatch interface, no native density fallback. Timesteps compare mass/material exactly and position/velocity with bounded fixture tolerances. Second consumption rejects. Scope is short fixture integration, not complete fluid production qualification.

Validation: 36 initial native tests, 86 extended native tests, 225 ordinary render tests passed (37 ignored); the dedicated ignored GPU test was run separately and passed. Logs and source hashes are adjacent. No CUDA or rendered FPS result is asserted.

Walls/images, polymer forces, transport and stepping retain native ownership. Late step failure preserves the previous complete Liquid state. ## Force-to-accumulation chain without an intermediate CPU read

`LiquidForcePipeline` compiles the existing force and accumulation shaders, records both passes in one caller-owned encoder and transfers the paired force/conductance words directly between GPU buffers. One final staging lease gathers both buffers for a single nonblocking read interface. There is no CPU mapping or wait between these two passes. Both compute jobs remain retained and charged until normal read completion; hardware assertions verify that storage charge and exactly one staging acquisition. The chain currently uses one GPU copy per pair and two storage buffers. It does not reuse persistent allocations across timesteps.

Transport admission checks the full upstream immutable prefix, complete force statuses and finite values. Only destination force slots may change, and every copied word must match the audited upstream output exactly. All other destination prefix words remain immutable. Corrupt statuses, topology, masses, gravity or transferred values reject the entire decode. Transport validation does not replace physical admission.

`LiquidForcePipelineOperator` and the optional joint backend capability connect this chain to the ordinary transactional liquid step. Every force is admitted against the original pair law, followed by original ordered accumulation using those admitted forces. Nothing is published on partial admission. Native regressions cover corrupt force, inconsistent acceleration, truncated force arrays and late step failure with exact equality of the retained complete state. The default native path does not advertise the capability.

Actual GPU tests passed for 70 particles and 2415 pairs, all three formulations, one submission and one staging lease per chain. Nine actual mixed-liquid timesteps (three per formulation) admitted the chain with no native fallback, at absolute 1e-12 and relative 2e-11; position/velocity bounds remain 1e-10/1e-9 and mass/material IDs are exact. The existing four-separate-stage GPU fixture also passed again. 143 native tests in 14 suites and 229 ordinary render tests passed (41 ignored).

This resident interval covers force-to-accumulation only. Density/normal/pressure preparation, whole physical reference checks and integration are not part of this GPU chain. The application backend remains a hardware test fixture using public compute APIs and the production stepping hook. Full resident state, GUI wiring, rendered FPS, CUDA and production qualification remain open. No speedup is claimed.

## Material pressure in the supported-normal GPU pass

Condensed pressure is c² max(rho-rho_ref,0); ideal-gas pressure is rho (c²/gamma), with gamma strictly greater than one. Material constants are prepared on the host, while current-density subtraction/clamping/multiplication runs in the existing normal pass. No additional dispatch or readback is introduced.
