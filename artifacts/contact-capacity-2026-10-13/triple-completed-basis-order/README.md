# Completed final QR basis with explicit row order

The experimental parallel triple shader now exports final active row order only on successful coordinate completion. A magic tag, selected count and selected row IDs occupy dead gap scratch (2+selected <= 3*rows words). No payload allocation, original coefficient, load or physical tolerance changes. This extends the ability to capture QR beyond previously known one-iteration seeded order.

completed_parallel_factors(full_readback) validates the complete original candidate, metadata tag/count, unique in-range rows and inclusion of every positive reaction row before retaining the compact selected Q/R and exact ordered vectors. reuse_completed_parallel_factors checks exact matching vectors/scales and uses private row-rank hints to restore the original basis order. The existing strict reuse API continues rejecting reordered active vectors. No mutation occurs on a coefficient mismatch. R restores using the fresh operator stride.

Validation: 18 regular triple renderer tests pass, including malformed final metadata, missing positive rows, duplicate/out-of-range IDs and unchanged input after mismatch. Actual GPU 91 x 882 capture completes cold in 11 iterations; its final basis restores in one iteration with bit-identical decoded motion and reactions. Original coordinate gaps pass. The legacy one-iteration snapshot can retain the explicitly reordered seeded result consistently. Existing factor/bounds/stride/active-row-extension GPU checks pass.

Five regular app solver tests and existing actual GPU independent physical scene, whole-batch failure/cache/retry checks and all three original native physical capture families pass after rebuilding with the shader change. These are regressions of the previous app integration: the app does NOT yet use completed_parallel_factors or reuse_completed_parallel_factors.

Current limitation: new completed-basis extraction requires full readback; compact extraction and app cache integration remain to be implemented and physically admitted. No native physical speedup or FPS claim. The separate full-cycle process remains on its frozen previous executable; its cache observation motivates this change but does not qualify it. The full engine goal remains incomplete.
